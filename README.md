# NutriWrist AI — 스마트워치 AI 영양 분석 웹앱

> 손목 위의 AI가 당신의 식사를 분석하고, 더 건강한 삶으로 안내합니다.

발표 자료(`AI.pptx`, 개발자 **박서현**, 2026.09.22)의 6개 슬라이드 내용을 **브라우저에서 직접 체험할 수 있는 인터랙티브 웹앱**으로 구현한 프로젝트입니다.
정적 사이트(HTML/CSS/JS)만으로 동작하며, 분석 파이프라인을 클라이언트에서 시뮬레이션합니다.

---

## 1. 프로젝트 목표 및 주요 기능

| 슬라이드 | 원본 내용 | 웹앱 구현 |
|---|---|---|
| 1 | 스마트워치 AI 영양 분석 기능 소개 | 히어로 섹션 + 스마트워치 목업(실시간 링/매크로) |
| 2 | 📸 촬영 → 🤖 AI 분석 → 🏃 운동 제안 | 3단계 "작동 방식" 카드 + 실제 분석 실행 흐름 |
| 3 | 🔥 칼로리 / 💊 영양소 / ⚠️ 알레르기 | **AI Food Scanner** — 샘플 선택 또는 사진 업로드 → 스캔 애니메이션 → 결과 카드 |
| 4 | 실시간 칼로리 추적 | 실시간 대시보드(SVG 링 + Chart.js 식사별 밸런스 차트) |
| 5 | 맞춤형 운동 제안 | 소모 목표 슬라이더 → MET 기반 6종 운동 자동 계산 |
| 6 | 건강 목표 달성 | BMR/TDEE 계산기 + 목표 유형별 자동 칼로리 조정 + 7일 리포트 |
| 추가 | (요청 기능) 대전 600kcal 이하 식당 | **대전 저칼로리 맛집** — 지역 필터 + 네이버 지도 딥링크 + 식단 기록 연동 |

### 핵심 체험 요소
- **음식 분석 시뮬레이터**: 샘플 음식 6종 선택 또는 내 사진 업로드 → 스캔 라인 애니메이션 → 칼로리·탄단지·미량영양소·알레르기 판정
- **재현 가능한 추론**: 이미지/음식 해시를 시드로 사용해 동일 입력 → 동일 결과 (신뢰도 88~98%, 1인분 보정 0.85~1.15)
- **알레르기 스캔**: 사용자 프로필(`계란`, `대두`, `유제품`)과 대조해 경고/안전 배너 표시
- **실시간 누적**: 분석 결과를 기록하면 워치 링, 대시보드, 차트, 주간 리포트가 즉시 갱신
- **맞춤 운동 계산**: `kcal/분 = MET × 3.5 × 체중(kg) / 200` 공식으로 소요 시간·소모 칼로리 산출
- **AI 목표 자동 계산**: Mifflin-St Jeor BMR × 활동계수(TDEE) × 목표계수(감량 0.82 / 유지 1.0 / 증량 1.15)
- **오프라인 폴백**: 테이블 API 실패 시 `localStorage`로 자동 전환하고 상태를 UI에 표시
- **대전 저칼로리 맛집**: 대전 5개 구(중구·서구·유성구·동구·대덕구) 12곳을 600kcal 이하로 큐레이션,
  지역 필터 + kcal 스케일 바 + 감량 팁 제공, 카드에서 **네이버 지도 검색**과 **식단 기록**을 바로 실행

## 4. 기능 진입 경로 (URIs)

| 경로 | 설명 | 파라미터 |
|---|---|---|
| `index.html` | 메인 페이지 | `#hero` `#how` `#analyze` `#track` `#workout` `#eat` `#goal` `#tech` |
| `GET tables/meals?limit=300` | 식사 기록 조회 | `limit`(기본 200), `page`, `search`, `sort` |
| `POST tables/meals` | 식사 기록 생성 | `food_id, name, emoji, image, kcal, carbs, protein, fat, meal_time, day, logged_at, allergens, source` |
| `DELETE tables/meals/{id}` | 식사 기록 삭제 (soft delete) | — |
| `POST tables/goals` | 목표 설정 저장 | `goal_type(lose\|keep\|gain), daily_kcal, activity_level, updated` |
| `localStorage` 키 | 폴백 저장소 | `nutriwrist.v1.meals`, `nutriwrist.v1.goal` |
| `map.naver.com/p/search/{키워드}` | 네이버 지도 검색 (외부 딥링크, 새 탭) | `키워드` = 예: `대전 은행동 샐러드` |

## 5. 데이터 모델

### `meals` (식사 기록)
`id`(text) · `food_id`(text) · `name`(text) · `emoji`(text) · `image`(text) · `kcal`(number) ·
`carbs`(number) · `protein`(number) · `fat`(number) · `meal_time`(text: 아침/점심/저녁/간식) ·
`day`(text: YYYY-MM-DD) · `logged_at`(text: HH:mm) · `allergens`(text, 콤마 구분) · `source`(text: demo/user)

### `goals` (건강 목표)
`id`(text) · `goal_type`(text: lose/keep/gain) · `daily_kcal`(number) · `activity_level`(number 1~5) · `updated`(text)

### 저장 서비스
- **RESTful Table API** (기본): `tables/meals`, `tables/goals`
- **localStorage** (폴백): API 접근 불가 시 자동 전환, 대시보드 "데이터 저장소" 패널에 현재 모드 표시
- **음식/운동 DB**: `js/foods.js` 내 정적 데이터 (실서비스에서는 온디바이스 NPU 추론 + 식약처 영양 DB로 대체)
- **대전 맛집 큐레이션**: `js/foods.js`의 `DAEJEON_SPOTS` (정적). 필드: `id, district, area, menu, emoji, keyword, kcal, carbs, protein, fat, note, tags`

## 5-1. 네이버 지도 연동 방식 (중요)

이 프로젝트는 **네이버 지도 검색 딥링크** 방식으로 연동했습니다. 이유는 다음과 같습니다.

| 방식 | 가능 여부 | 설명 |
|---|---|---|
| 지도 임베드 (JavaScript API v3) | ❌ 불가 | **Client ID 발급 + 등록 도메인**이 필요하며, 이는 서버에서 관리해야 하는 인증 정보입니다. 정적 사이트 코드에 키를 넣으면 소스에서 그대로 노출되어 누구나 무단 사용할 수 있습니다. |
| 지도 임베드 (iframe) | ❌ 부적합 | 검색 결과를 직접 띄우는 정식 방법이 아니며, 네이버 정책상 무단 임베드에 해당할 수 있습니다. |
| **검색 딥링크** | ✅ 사용 중 | `https://map.naver.com/p/search/{키워드}` — 키가 필요 없고, 사용자를 네이버 지도 앱/웹의 최신 데이터로 보냅니다. |

**결과적으로** 이 섹션은 "대전 실제 행정동 + 저칼로리 메뉴 유형"을 조합해 제공하고, 실제 상호·영업시간·가격은
네이버 지도에서 확인하도록 연결합니다. 특정 업체를 지정한 추천이 아니므로 영업 여부가 변동되어도 안내가 틀리지 않습니다.

> 실제 서비스에서 지도를 페이지 안에 띄우려면 서버리스 프록시(예: Cloudflare Worker)로 Client ID를 숨기고
> 도메인을 등록한 뒤, 그 프록시를 통해서만 지도 API를 호출하는 구조가 필요합니다.

## 6. 아직 구현되지 않은 기능

- 실제 이미지 인식(CNN/Vision Transformer) 추론 — 현재는 해시 기반 결정론적 시뮬레이션
- 바코드 스캔, 식약처/Open Food Facts 실시간 영양 DB 연동
- 사용자 계정·로그인 및 기기 간 동기화
- 스마트워치 네이티브 앱(워치OS/Tizen) 및 실제 센서(심박·걸음수) 연동
- 알레르기 프로필 사용자 편집 UI (현재 `js/foods.js`의 `USER_ALLERGENS` 상수)
- 목표 대비 체중 변화 추이(체중 기록) 및 영양소 상세 리포트 내보내기
- 사진 업로드 시 서버 측 저장(정적 사이트 한계로 브라우저 내 처리만 지원)
- **네이버 지도 페이지 내 임베드**(Client ID·도메인 등록 필요, 정적 사이트 불가)
- 실제 식당 상호·영업시간·가격 데이터 연동(현재는 메뉴 유형 큐레이션 + 지도 딥링크)
- 위치 기반 자동 추천(GPS 현재 위치 → 주변 저칼로리 식당 정렬)
- 리뷰·평점 연동 및 사용자 즐겨찾기 저장

## 7. 다음 개발 단계 제안

1. `USER_ALLERGENS`를 `profiles` 테이블로 분리하고 설정 UI 추가
2. 음식 DB를 `foods` 테이블로 이관해 관리자가 항목을 추가/수정할 수 있게 개선
3. 체중 기록(`weights` 테이블) 추가 → 목표 달성 예상일 계산
4. PWA(Service Worker + manifest) 적용으로 오프라인 사용 및 홈 화면 설치 지원
5. 주간/월간 리포트를 CSV 또는 이미지로 내보내는 클라이언트 사이드 기능
6. 접근성 강화: 차트 데이터 테이블 대체 텍스트, 키보드 전용 조작 흐름 점검
7. `DAEJEON_SPOTS`를 `spots` 테이블로 이관해 사용자가 맛집을 추가/평가할 수 있게 개선
8. 지도 임베드가 필요하면 Cloudflare Worker 프록시로 네이버 지도 Client ID를 숨기는 구조 도입

## 9. 주의 사항

본 페이지는 **발표용 데모**입니다. 영양 수치는 1인분 기준 참고용 추정값이며 의학적 진단이 아닙니다.
실제 서비스에서는 온디바이스 NPU 추론과 공인 영양 데이터베이스를 사용해야 합니다.

**대전 저칼로리 맛집 섹션**의 kcal은 해당 메뉴 유형의 일반적 1인분 추정값이며,
특정 업체를 지정한 추천이 아닙니다. 실제 매장의 조리법·제공량·영업 여부는 네이버 지도에서 확인하세요.
